# recon 1.0 phase 2b — the keymap in the config file

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user rebind any action in `config.toml`, and let recon print its own default keymap in the syntax that file accepts.

**Architecture:** The compiled-in table from plan 2a becomes the base layer of a runtime `Keymap`. A `[keymap]` stanza in `config.toml` overlays it at load, with every action name and key spelling checked there rather than at the keypress. A new `--print-keymap` hand-formats the whole default table, exactly as `--print-editor-config` hand-formats the `[editor]` stanza.

**Tech Stack:** Rust 2024, `toml` (deserialise only), crossterm 0.29.

**Spec:** `docs/specs/2026-09-11-recon-1.0-release-design.md`, section 5, "Phase 2 — Keymap architecture (5)".

**Scope:** This is plan **2b** of two, and it requires plan 2a to have landed. 2a covers #59, #250, #199 and #178, and leaves the table compiled in. 2b covers **#61** and the two reserved keys, and makes the table overridable.

## Global Constraints

- **Add no dependency.** `toml` and `crossterm` are already here.
- **recon never writes `config.toml`.** This is enforced in `Cargo.toml:115-125`, which drops `toml`'s `display` feature so the serializer does not exist in this build. Every stanza recon emits is hand-formatted with `format!` and printed for the user to paste. Do not add the feature, and do not add a write path.
- **Clippy pedantic is on and CI fails on any warning.** `cargo clippy --workspace --all-targets -- -D warnings` must be clean. Prefer fixing a site to adding an `allow`; a new `allow` needs a written reason.
- **CI runs three commands, and all three must pass before every commit:** `cargo fmt -p recon --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- **Comments say why, not what**, and carry the issue number for a non-obvious decision.
- **Each commit body ends with `Closes #NNN`** for an issue it finishes.

## The facts this plan rests on

**What plan 2a produced**, in `src/keymap.rs`: `Key { code, ctrl, alt }` and `normalise(KeyEvent) -> Key`; `Scope { Prompt, Help, Picker, Global, Nav, View, Filters }`; `ActionId` with `name(self) -> &'static str`; `DEFAULT: &[(Scope, &str, ActionId)]`; and `resolve(Scope, Key) -> Option<ActionId>` scanning `DEFAULT`. In `src/help.rs`: `Binding` carries `names: &'static [&'static str]`, and `label_matches(label, Key) -> bool` parses the shared label grammar.

**The interface 2b changes, and why 2a did not write it this way.** 2a's `resolve` is a free function over a `const`, which is correct while the bindings have exactly one source. A config overlay gives them a second, so the table becomes runtime state: `resolve` becomes a method on a `Keymap` value that `App` owns. Doing that in 2a would have added a field nothing could yet vary.

**What 2a left for this plan to close.** Four things, three of them consequences of the table being a `const` and the fourth found by 2a's final whole-branch review.

1. **`label_for` reads the `const`.** `keymap::label_for` scans `DEFAULT` for the first row naming an action, and `hint_for` builds every on-screen key hint from it. Task 4 below removes every default entry for a rebound action before adding the user's keys — so `resolve` would honour the new key while every hint went on naming the old one. `hint_for`'s own doc comment says "the hint tracks a rebind for free"; that is true only once `label_for` consults the `Keymap` rather than `DEFAULT`. Move it there in Task 4, not later: the failure is silent, and it defeats the point of generating the hints at all.
2. **Nothing in 2a can prove that mechanism.** All fourteen hint assertions pin default-keymap output, so not one would fail if the generated text regressed to hard-coded strings. The test that proves it — rebind an action, assert its hint names the new key — cannot be written until this plan exists. Write it, and it catches (1) as well.
3. **`label_for` ends in `.expect("every action passed to hint_for has a DEFAULT row")`.** Unreachable today. If an overlay can leave an action with no keys at all, it becomes reachable, and a typo in `config.toml` must not panic the TUI — the rule `App::perform`'s `debug_assert!` arms already follow for the same reason.
4. **`Focus::View`'s fallthrough forwards unresolved keys raw.** When `resolve(Scope::View, …)` finds nothing, `App` forwards the original event and `FileView::handle_events` matches on the character alone, so an unbound *modified* key — `Alt-j`, say — still moves the cursor. The navigator and the filter pane both drop an unresolved key instead; the view is the one exception, and 2a's final review proved it by running the program. No existing test constrains the behaviour, so closing it means writing the tests too. Note the second-order effect: `FileView::handle_events` promotes a truncated preview on entry, so today an unbound modified key also forces that load.

**How the config layers work.** `Config::load` (`src/config.rs:667-672`) is `Self::parse()`, then `check_flags()`, then `apply(&load_file()?)`. `Config::apply` (`src/config.rs:674` onward) **exhaustively destructures** `FileConfig`, and its doc comment says why: "add a field to `FileConfig` and this stops compiling until the new setting is actually merged here". So adding `keymap` to `FileConfig` forces the merge to be written.

**The stanza pattern.** `FileConfig` (`src/config.rs:255-272`) holds `Option<EditorConfig>`, `Option<ClipboardConfig>`, `Option<FiltersConfig>`, `Option<SyntaxConfig>`, `Option<ViewConfig>`. Each stanza struct derives `Deserialize, Debug, Default, PartialEq, Eq` and carries `#[serde(deny_unknown_fields)]`. Absent and present-but-empty are deliberately different only in that neither sets anything.

**Parse spellings at load, not at use.** `SyntaxConfig::theme` uses `#[serde(default, deserialize_with = "theme_spelling")]`, and its comment gives the reason: "so that a typo names the file and the line rather than surfacing at the first `.rs` opened". A keymap typo must not surface at the first keypress three hours in.

**Error shape.** `ConfigError` (`src/config.rs:431-457`) has `UnknownSet { name, known }` and `UnknownProfile { set, name, known }` — a bad value, plus the valid ones. `known_list(&[String]) -> String` renders the list, or `none` for an empty one. The `Display` impl is at `src/config.rs:459-497`.

**The emitter precedent.** `print_editor_config` (`src/editor.rs:675-702`) returns a `String` and prints nothing itself. It leads with comment lines including `# Paste into ~/.config/recon/config.toml — recon never writes it for you.` and quotes values with `toml_string` (`src/editor.rs:710-716`), which is **private to that module** today. `main.rs:27-36` holds its early return, placed above `filtersets::load_file()` by #191 because the command reads nothing from `filters.toml`.

**Test shapes that already exist.** Unit: `fixture("view-center-off.toml", "[view]\ncenter_jumps = false\n")`, then `load_from(&path)`, then `config.apply(&file)` — see `center_jumps_is_on_unless_the_file_turns_it_off` (`src/config.rs:1643`). Rejection: `an_unknown_key_inside_view_is_rejected_and_named` (`src/config.rs:1654`) asserts the message names the offending key. End to end: `config_home(dir)` (`tests/headless.rs:27`) writes a config home and `recon(home, args, stdin)` runs the binary against it.

**An open question this plan must not answer on its own.** #247 records that `--print-editor-config --set Bogus` prints and exits 0 rather than refusing, and that the right behaviour is undecided. `--print-keymap` joins that family and inherits the same question. Task 2 gives it the same behaviour as its sibling and nothing more; whatever #247 decides should then change both together.

```rust
/// Render the whole default keymap as a `[keymap]` stanza.
///
/// A `String` returned to the caller to print, and nothing else — the same
/// contract `print_editor_config` has, and for the same reason: recon does not
/// write `config.toml`, so what it can do is hand you the text.
///
/// Printed in the syntax the file accepts, so copying one line and changing
/// the key is the whole of rebinding (#61). Grouped by scope and printed in
/// table order, which is the order the help overlay shows.
pub(crate) fn print_keymap() -> String {
    let mut out = String::from(
        "# recon's default keymap\n\
         # Paste into ~/.config/recon/config.toml — recon never writes it for you.\n\
         # Keep only the lines you want to change; anything absent keeps its default.\n\
         [keymap]\n",
    );

    let mut last_scope = None;
    for (scope, label, action) in DEFAULT {
        if last_scope != Some(*scope) {
            out.push('\n');
            last_scope = Some(*scope);
        }
        // One line per binding rather than one per action, even where two keys
        // share an action: a user who wants to move `u` reads the `u` line.
        // An array is accepted on the way back in, so a hand-merged
        // `["u", "H"]` still works.
        out.push_str(&format!(
            "{} = {}\n",
            toml_string(action.name()),
            toml_string(label)
        ));
    }
    out
}
```

```rust
/// The `[keymap]` table: which keys reach which action.
///
/// Action to key, and not the other way round, for two reasons. It is the
/// direction `--print-keymap` prints, so a pasted line reads as it was
/// printed. And an action may hold several keys, which a key cannot.
///
/// A `BTreeMap` rather than named fields: the keys are action names, there are
/// about ninety of them, and `deny_unknown_fields` cannot help here — an
/// unknown action is caught by `Keymap::new`, which can say which names exist.
#[derive(Deserialize, Debug, Default, PartialEq, Eq)]
#[serde(deny_unknown_fields)]
pub struct KeymapConfig {
    #[serde(flatten, deserialize_with = "one_or_many")]
    pub bindings: std::collections::BTreeMap<String, Vec<String>>,
}
```

`one_or_many` accepts a bare string or an array of strings for each value, so both forms in the first test parse. Add `pub keymap: Option<KeymapConfig>` to `FileConfig`, with the same "absent and present-but-empty differ only in that neither sets anything" comment its siblings carry.

- [ ] **Step 3: Write it**

```rust
/// Every binding in force, the defaults with the user's changes folded in.
///
/// Built once at startup and then only read. A `Vec` scanned linearly, for the
/// reason the `DEFAULT` scan gives: about 130 entries, consulted once per
/// keypress, which is an event a human produced.
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct Keymap {
    entries: Vec<(Scope, &'static str, ActionId)>,
}
```

`Keymap::default()` is `DEFAULT` collected. `Keymap::new` starts from the defaults and, **for each action the overlay names, removes every default entry for that action first, then adds the user's keys**. That is what the first test pins: a rebound action must not answer to its old key as well, or `q` would both quit and do whatever the user moved onto it.

An action name that is not in `ActionId` is `ConfigError::UnknownAction`, with every `ActionId::name()` as `known`. A label that `label_matches` cannot parse is `ConfigError::BadKeyLabel`.

`resolve` becomes a method with the same body the free function had, scanning `self.entries`. Delete the free function; update its call sites from plan 2a, which are `App::dispatch_event` and the widget test helpers.

`App` gains a `keymap: Keymap` field, built in `App::new` from the config.
