# recon 1.0 phase 2a — the keymap table

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every key binding a scoped action name, resolve keys through one table instead of eight scattered `match` sites, and remove the cause of #250.

**Architecture:** A new `src/keymap.rs` owns a table mapping `(Scope, Key)` to an `ActionId`. Keys are normalised as they enter the table, which replaces the three competing modifier idioms with one rule. `App::dispatch_event` resolves a key to an action once, then performs it; the panes receive actions instead of deciding whether a key is theirs.

**Tech Stack:** Rust 2024, crossterm 0.29, ratatui 0.30.2, the vendored `tui-textarea` fork.

**Spec:** `docs/specs/2026-09-11-recon-1.0-release-design.md`, section 5, "Phase 2 — Keymap architecture (5)".

**Scope:** This is plan **2a** of two. It covers #59, #250, #199 and #178. Plan 2b covers #61 — the `[keymap]` stanza, `--print-keymap`, and the reserved keys `-` and `:`. 2a leaves the table compiled-in and unconfigurable; 2b makes it overridable.

## Global Constraints

- **Add no dependency.** Everything needed is in `crossterm`, `ratatui` and `std`.
- **Clippy pedantic is on and CI fails on any warning.** `cargo clippy --workspace --all-targets -- -D warnings` must be clean. Prefer fixing a site to adding an `allow`; a new `allow` in `Cargo.toml` needs a written reason.
- **CI runs three commands, and all three must pass before every commit:** `cargo fmt -p recon --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- **Comments in this repo say why, not what**, match the density and tone of the code around them, and carry the issue number for a non-obvious decision.
- **The TUI draws on stderr** (#143). Nothing in this plan prints to stdout.
- **Each commit body ends with `Closes #NNN`** for an issue it finishes.
- **Do not change what any key does.** This plan moves *where* a binding is decided, not *what* it does — with exactly one deliberate exception, #250, which is Task 5.

## The facts this plan rests on

Verified by a survey and re-checked against source. Do not re-derive these; do not contradict them.

**The eight key sites.**

| # | Site | Location | Signature / return |
|---|---|---|---|
| 1 | `App::dispatch_event` global match | `src/lib.rs:1352-1757` | `()`, early `return` per arm |
| 2 | `App::handle_search_key` | `src/lib.rs:727-838` | `()` — runs before everything while `search.is_some()` |
| 3 | `App::handle_filter_key` | `src/lib.rs:2535-2598` | `()` — only when `focus == Filters` |
| 4 | `long_range_target` | `src/viewport.rs:50-73` | `Option<usize>`, pure |
| 5 | `FileNav::handle_events` | `src/widgets/filenav.rs:490-548` | `(&mut self, Event) -> Option<Action>` |
| 6 | `FileView::handle_events` | `src/widgets/fileview.rs:997-1124` | `(&mut self, Input)` — tui-textarea `Input`, not `KeyCode` |
| 7 | `FilterList::handle_key` | `src/widgets/filterlist.rs:201-288` | `(&mut self, KeyEvent, &[Row]) -> Option<FilterCommand>` |
| 8 | `Picker::handle_key` | `src/widgets/picker.rs:63-86` | `(&mut self, KeyEvent) -> PickerOutcome` |

**The precedence `dispatch_event` already runs**, which the `Scope` enum must reproduce exactly: open prompt (`search.is_some()`) → help overlay → picker → the `swallow_next_enter` bounce guard → global match → `handle_filter_key` when `focus == Filters` → `long_range_target` when `focus == View` and modifiers are empty → the focused pane.

**Modifiers.** crossterm attaches `SHIFT` only when `c.is_uppercase()` — `char_code_to_event`, `crossterm-0.29.0/src/event/sys/unix/parse.rs:128-135`. recon never enables the keyboard-enhancement flags, so it always runs in this legacy mode. `char::is_uppercase` is **false for punctuation**, so `{`, `}`, `?`, `*`, `!` and `&` arrive with no modifier at all; only uppercase *letters* carry `SHIFT`.

**Which file-view arms are dead, and which are not.** `long_range_target` intercepts `g`, `G`, `Home`, `End`, `{`, `}` under `modifiers.is_empty() && focus == View`. So:

- `g`, `Home`, `End`, `{`, `}` reach it and **never** reach `FileView`. Those five `FileView` arms are dead code.
- `G` carries `SHIFT`, fails `is_empty()`, and **does** reach `FileView`, which runs `CursorMove::Bottom` — the bottom of the loaded buffer rather than the document. That is #250, and `G` is the only key with the fault.

**Why the tests never caught it.** `key()` at `src/lib.rs:3745-3747` builds events with `code.into()`, which sets no modifier whatever the case. `press_mod` at `src/widgets/filenav.rs:2506` is the existing precedent for doing it correctly.

**Three arms are forwarders or hints, not bindings.**
- `[` and `]` at `src/lib.rs:1536-1541` only call `forward_to_view(event)`; the behaviour lives in `FileView`'s own arms. They must not become separate actions.
- `i`, `x`, `c`, `d`, `m`, `a`, `s` in the global match, and `h`/`l` in `handle_filter_key`, only call `self.report(...)` with a hint such as `"i adds a filter · f i"`. They are not bindings. Task 8 replaces them with generated text.
- `v`, `V`, `y` and `*` are single global arms that branch on focus internally, acting only when `focus == View` (or `Filters`, for `*`). They are one action each, not two.

**The `f` chain.** `f` sets `chain_origin` and focuses the filter pane. Committing an `i`/`x`/`c` prompt calls `return_to_chain_origin` (`src/lib.rs:2886-2902`), which restores focus and dispatches a **synthetic `n` key event** through `dispatch_event`, then re-arms `swallow_next_enter`.

**Test inventory that must stay green:** ~430 `#[test]` in `src/lib.rs` driving `key()`/`ctrl()`, 90 in `fileview.rs` via `send(view, key)` building `Input`, 94 in `filenav.rs` and 54 in `filterlist.rs` via `press()`/`press_mod()`.

```rust
use crossterm::event::{KeyCode, KeyEvent, KeyModifiers};

/// A key as the table stores it: the code, and the two modifiers that carry
/// meaning.
///
/// `SHIFT` is deliberately absent. In the legacy key-reporting mode — which is
/// the only mode recon runs in, because it never pushes the keyboard
/// enhancement flags — crossterm attaches `SHIFT` exactly when the character
/// is uppercase (`char_code_to_event` in crossterm's unix parser). So for a
/// letter the modifier repeats what the `char` already says, and for
/// punctuation it is never set at all: `{` is not "shifted `[`" as far as the
/// terminal is concerned, it is the character `{`.
///
/// Keeping it would mean every table entry had to guess which of the two
/// spellings a terminal would send. That guess is what #250 was: `G` arrived
/// carrying `SHIFT`, failed an `is_empty()` guard written for keys that never
/// carry it, and fell through to a handler that answered the wrong question.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub(crate) struct Key {
    pub(crate) code: KeyCode,
    pub(crate) ctrl: bool,
    pub(crate) alt: bool,
}

/// Put a keypress in the table's currency.
pub(crate) fn normalise(event: KeyEvent) -> Key {
    Key {
        code: event.code,
        ctrl: event.modifiers.contains(KeyModifiers::CONTROL),
        alt: event.modifiers.contains(KeyModifiers::ALT),
    }
}
```

```rust
/// Where a key is looked up, in the order `dispatch_event` already checks.
///
/// The first four are modal: while one is active it owns the whole keyboard
/// and nothing below it is consulted. The last three are the panes, chosen by
/// which one has focus.
///
/// `Ord` is derived and load-bearing: the discriminant order *is* the
/// precedence, and a test asserts it, so a variant reordered for tidiness
/// cannot silently change which handler sees a key first.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub(crate) enum Scope {
    /// A search or filter prompt is open. `handle_search_key` owns every key.
    Prompt,
    /// The help overlay is up, and any key closes it.
    Help,
    /// The profile picker is open.
    Picker,
    /// Checked for every key that no modal scope claimed.
    Global,
    Nav,
    View,
    Filters,
}

impl Scope {
    /// The pane scope for the focused pane.
    pub(crate) fn for_focus(focus: crate::widgets::Focus) -> Self {
        match focus {
            crate::widgets::Focus::Nav => Self::Nav,
            crate::widgets::Focus::View => Self::View,
            crate::widgets::Focus::Filters => Self::Filters,
        }
    }
}
```

```rust
/// Whether a `KEYMAP` label names this key.
///
/// The label grammar is the one `Binding::codes` already parses, so the
/// documentation, the table and a user's config file all spell a key the same
/// way. `Ctrl-` and `Alt-` prefixes set the two modifiers the table keeps;
/// everything else is the bare key.
pub(crate) fn label_matches(label: &str, key: crate::keymap::Key) -> bool {
    let ctrl = label.starts_with("Ctrl-");
    let alt = label.starts_with("Alt-");
    if ctrl != key.ctrl || alt != key.alt {
        return false;
    }
    Binding { keys: &[label], action: "", name: None }
        .codes()
        .any(|documented| match (documented, key.code) {
            (Key::Char(c), crossterm::event::KeyCode::Char(pressed)) => c == pressed,
            (Key::Named(name), code) => named_matches(name, code),
            _ => false,
        })
}
```
